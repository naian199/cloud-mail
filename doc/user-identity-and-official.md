# 用户身份与官方认证（1.23.0）

用户 ID 保持现有的永久主键，`mail_user_handle` 继续作为唯一用户名来源，不建立第二套账号。新注册用户名为4–24位 ASCII 字母、数字和下划线，字母开头，去首尾空格、转小写；系统用途名称禁止新领取。昵称独立且可重复。首次用户名同时作为默认邮箱前缀，邮箱域名取后台配置；隐藏登录域名时提供默认注册域名。后续不开放用户名修改或删除，已有3位或保留名称的历史用户名不被改写，仍能搜索和登录。昵称可修改。

注册使用同一个 D1 batch 创建 user、handle、account 和 profile，任意约束失败整体回滚。已有 NOCASE 唯一约束保证全站用户名唯一，新增 account 插入触发器禁止再次创建已有地址（包括已软删除的地址），不扫描删除历史重复数据。不允许注册时替换其他用户的用户名。兼容旧注册客户端的 email 参数，以邮箱前缀领取用户名，同样执行新规则。旧用户继续使用原完整邮箱登录；无用户名时可在个人设置领取，不创建额外邮箱。用户名、完整主邮箱和有效的附属邮箱都可登录，禁用用户仍不可登录。用户名不能用来证明密码找回身份。

注册可用性接口同时检查用户名、邮箱占用及后台前缀策略。每个访问 IP 每分钟最多30次，数据库仅短期保存 IP 的 SHA-256 摘要，清理超过10分钟的窗口。前端450ms防抖、请求序号防止乱序结果，网络失败不会显示可用。接口只能提示可用性，最终以提交事务约束为准。OAuth 首次绑定仍由用户选择本网站邮箱前缀，并经过相同用户名及邮箱创建路径；已经绑定账号继续走原登录路径，不重新注册。

## 官方认证

独立的 `mail_official_identity` 保存有效状态、公开主体、公开说明、授予管理员 ID 与更新时间；`mail_official_audit` 保留每次授予、撤销及操作人记录，删除用户不级联删除审计。后台目前展示最近50条历史，数据库不截断。注册和资料修改不接收认证字段。用户名、邮箱或昵称文字不会推断为认证。标志使用后端字段，昵称始终纯文本插值。

网站主管理员可操作，也可在权限控制中明确授予新权限 `user:verify`；迁移不自动把该权限分配给现有普通角色。服务层重新查询操作者当前状态与权限。持有认证的账号不自动拥有任何后台权限。用户管理页面提供授予、撤销、公开主体与说明及审计查询，认证说明不公开管理员的私人信息。

会话列表、聊天标题、资料、联系人与搜索结果、群消息发送人和成员列表共用认证组件。支持点击、触摸与键盘查看说明。更新后通知对应联系人和群组，正常轮询同时校准数据；群组增量拉取会校准当前已加载发送人的认证状态，避免没有新消息时旧标志残留。断线或休眠客户端需要恢复连接后才能刷新；不保证断网设备立即撤销显示。

## 迁移与回滚

`mail_chat_schema_v11` 只添加认证、审计、查询限流表、权限项与新地址防重复触发器，不批量重命名、不自动领取、不自动授予认证。历史3位用户名正常保留。生产环境账号量、重复邮箱和遗留保留名称尚未在本地检验，运行 `scripts/audit-user-identity.sql` 可只读检查；存在问题时人工评估，不自动修复。首次请求会按项目既有机制执行幂等增量建表。

推荐发布前备份 D1。回滚应用代码可保留新增表及用户名数据，不需要删除用户、邮箱或聊天记录；用户名仍属于原用户 ID。若因特殊旧客户端需要撤回新增邮箱插入约束，应单独评估并移除 `mail_identity_mailbox_unique` 触发器，此操作会失去新地址的并发防重复保护，不随应用回滚自动执行。

本地验证覆盖大小写冲突、同名并发、事务回滚、保留名、用户名及邮箱登录、旧用户领取、普通用户越权、认证授予/撤销/审计、手机注册、默认域名隐藏和管理页面。未使用真实 Google/GitHub 授权账号完成外部 OAuth 往返测试，也未自动给生产用户补齐用户名或认证。新增身份和认证文案提供中文与英文，其余语言暂采用英文文案。
