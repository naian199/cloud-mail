# 消息预览与后台推送

版本：1.12.1。

## 开启

在“个人设置 → 消息提醒”点击“开启此设备通知”，由用户在浏览器或系统弹窗中允许。每个设备单独开启，最多 5 个订阅。iPhone/iPad 需要 iOS/iPadOS 16.4 或更新版本，先添加到主屏幕，再从应用图标打开并授权。浏览器权限被拒绝时，需要用户在系统或网站设置中重新允许。

预览可选择“发送人和正文”“仅发送人”“仅提示有新消息”。私聊、站外邮件、群聊、频道可分别开关。预览、范围和会话静音在账号设备间同步；“关闭此设备通知”仅取消本设备系统推送，不修改其他设备。网页前台的站内提醒仍由账号总开关控制。

私聊和站外邮件可在会话列表右键菜单静音；群聊与频道可在会话标题栏点击铃铛。点击通知打开对应会话，邮件和群消息携带定位信息；登录失效时仍需重新登录。

## 浏览器标签提醒

标签标题显示未读数量，最多显示 `99+`；网站图标叠加红点，没有未读时恢复。计数覆盖当前账号各邮箱、已加入的群聊与频道，不包括自己的群消息、已删除邮件或重复邮件副本。关闭系统通知或静音不隐藏未读状态，标签不显示发送人或正文。后台通过现有 WebSocket 更新，断线时每 15 秒核对；浏览器冻结或休眠标签时可能延迟，恢复后重新同步。其他窗口读完消息后同步清除，退出登录清除本页角标。

## 安装后的应用角标

支持 Badging API 的浏览器或已安装 PWA 会自动设置未读数，归零时清除。iPhone/iPad 需要 16.4 或更新版本、添加到主屏幕并允许通知；Windows、macOS、Android 的显示受浏览器、启动器、系统徽标设置影响，可能显示数字、圆点或不显示，不承诺所有环境一致。应用角标独立于网页图标红点；系统通知的 `badge` 小图标也不是应用未读数。

前台及后台标签每次核对未读时更新；关闭页面后，新消息推送由 Service Worker 更新。推送和查询携带计数快照时间，IndexedDB 原子校验当前账号与快照顺序，较旧推送不会覆盖较新的已读计数。退出或切换账号清除旧角标，不支持或权限拒绝时静默降级，不阻断聊天。

完全关闭应用时，其他设备已读后的清零会延迟到本设备下次打开或收到后续推送。不发送只有角标、没有可见通知的静默推送，因为浏览器的 `userVisibleOnly` 要求及 iOS 限制不能保证这种用法可用。系统通知被划掉不等于消息已读。真实手机主屏幕、桌面任务栏显示仍需设备验收。

## Ferdium 左侧服务图标

Ferdium 的 Custom Website 通用服务脚本默认不读取网站未读数。网站从 1.12.1 起直接调用其页面桥 `window.ferdium.setBadge(未读总数, 0)`；这是独立于网页 favicon 和 Badging API 的 Ferdium 宿主接口，无需额外安装网站插件。计数覆盖当前账号站内私聊、外部邮件、群聊与频道，不依赖浏览器通知授权；已读、退出后传 0。超过 99 的真实数字照常传给 Ferdium，由它决定显示样式。

发布后在 Ferdium 内重新加载邮箱服务，检查未关闭该服务的未读角标、服务未被暂停或休眠。角标由 Ferdium 本身渲染；不提供上述桥接的旧版本需要升级。接口缺失或调用失败时保留其他提醒，恢复焦点和桥接迟到后会重试同步，不访问 Electron 通用 IPC、文件或账号密钥。

接口来源：[Ferdium 页面桥](https://github.com/ferdium/ferdium-app/blob/develop/src/webview/recipe.ts)、[未读 IPC 处理](https://github.com/ferdium/ferdium-app/blob/develop/src/webview/badge.ts)、[Custom Website 脚本](https://github.com/ferdium/ferdium-recipes/blob/main/recipes/franz-custom-website/webview.js)。自动化测试模拟该窄接口检查调用参数、迟到注入、重连、跨窗口已读与退出；未把模拟接口当成真实 Ferdium 客户端实测。

## 行为与边界

- 网页前台由 Service Worker 交给一个可见、获得焦点的窗口显示站内预览；当前会话不重复打扰。后台使用系统通知，多标签及重复事件去重。
- 图片、视频、语音和文件使用类型提示，不下载附件来生成提醒。短小的可用头像可以作为图标，系统也可能使用应用图标；iOS 的显示由系统决定。
- 同一会话通过推送服务 Topic 和系统 tag 合并。单批最多四个具体会话加一个汇总提醒，所有消息仍保留在未读列表中。
- 仅从有权限、未删除、未读的新消息构建提醒，群组需要当前已加入，频道遵循既有成员与发布权限。通知生成时校验；已入队或系统已经展示的通知可能延迟出现，隐私更改不能保证撤回其他设备的旧通知。
- 临时失败从 15 秒逐步退避到 1 小时，最长重试窗口 24 小时；服务端及推送服务保留有效期最多 24 小时。404/410 端点移除。重新开启会建立当前消息基线，避免把关闭通知期间的旧记录当新提醒。
- Web Push 是尽力送达机制。系统省电、专注模式、网络、强制退出浏览器、权限关闭等会影响及时性，不能保证每条消息始终即时到达。锁屏是否显示正文还由系统设置决定。

## 安全与部署

使用 `@block65/webcrypto-web-push` 2.0.0 的 RFC 8291 AES128GCM 与 RFC 8292 VAPID，密文填充为固定 4096 字节。VAPID 私钥存于既有 `CHAT_NOTIFICATIONS` Durable Object 的专用对象，不返回前端，不随普通发布重新生成。服务端在加密前执行隐私设置，不把消息正文、订阅密钥写入日志。

不需要另填 Google API 密钥。沿用现有 Worker、D1 和 Durable Object；迁移只新增偏好和订阅表。订阅需要登录，仅允许已知浏览器推送服务 HTTPS 端点，拒绝任意源站、凭据和私网地址。

Service Worker 不持有登录令牌，不缓存私人邮件或 API，只保存本机当前账号标识、通知偏好与去重标识。退出登录清理身份、尝试取消订阅并关闭通知；切换账号不会把旧账号提醒显示给新账号。Service Worker 的静态缓存仍只涉及安装图标。

部署域名继续固定为 `e.naian.edu.kg`。

## 验证及首次设备验收

- 单元测试：预览隐私、端点限制、Web Push 加密与独立解密、系统通知去重、账号隔离、通知点击安全、角标调用顺序和 API 不可用降级。
- 本机 Worker 集成：私聊与群聊预览、静音、退群、权限、设置版本、订阅所有权和并发设备上限。
- 浏览器：通过 DevTools 模拟 Push 事件触发真实 Service Worker，验证前台预览、后台系统通知、点击定位、当前会话抑制、隐私切换与关闭本机通知。应用角标测试使用真实 Service Worker、IndexedDB 与模拟平台角标 API，覆盖前台计数、跨窗口已读清零、后台推送、旧快照与账号隔离、退出清除。并未把模拟事件当成真实推送服务、系统启动器图标或手机锁屏送达测试。

首次上线后，请分别在电脑和手机开启通知，再用另一账号发送私聊、群聊、频道和外部邮件，测试切换后台、锁屏、隐私模式、静音与退出登录。真实手机锁屏送达尚需实际设备完成验收。
