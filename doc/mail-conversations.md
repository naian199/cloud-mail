# 邮件聊天模式

登录后的首页现在是「邮件会话」：联系人在左侧，往来邮件用左右气泡展示。手机端先显示会话列表，进入聊天后可以返回。侧边栏的「收件箱」「已发送」等原有入口保留；「好友聊天」仍是单独的站内私聊功能。

## 收发与会话规则

- 使用已有邮件记录及邮件服务。站内邮件继续直接投递到对方邮箱；站外邮件继续通过配置的 Cloudflare Email Service 或 Resend 投递。外部邮件到达后才更新界面，不保证外部邮件像站内消息一样立即送达。
- 每个邮箱独立组织会话，不跨邮箱混合数据。同一联系人的不同主题聚合为同一会话，标题保留在原邮件中，气泡只显示本次正文；多人邮件按可见 To/Cc 参与者集合形成独立会话。
- Reply-To 优先于发件地址。默认回复发件方，多人会话可以明确选择「回复全部」；BCC 不会被加入回复全部，也不会用于向其他联系人展示参与者。
- 回复保存 Message-ID、In-Reply-To 和完整 References 链；新发件请求生成 Message-ID。外部服务是否保留自定义 Message-ID 仍需实际服务验证，服务商返回的邮件记录 ID 不会冒充 RFC Message-ID。
- 已收到、已提交发送和已投递使用实际邮件状态。Cloudflare 服务接受发送不再直接显示为已投递；已有 Resend 投递回调或站内实际入库后才更新状态。没有已读回执时不显示对方已读。
- 每次加载最多 20 封会话消息、30 个会话。历史邮件按每批 100 封增量建立索引，原始正文、标题、附件和标识不变。首次进入大邮箱时会话会逐步出现。
- 收信使用邮箱和 Message-ID 去重。已有历史重复记录不会被物理删除，聊天展示与未读数按邮件标识兼容去重。

## 草稿、附件与安全

普通回复和新会话都可以添加附件，最多 10 个、总大小 10 MB。附件仍使用项目的 KV/R2/S3 存储逻辑。新增下载接口逐次检查登录、邮箱、邮件及附件归属；下载时使用附件响应并禁止内容类型嗅探。

时间按聊天习惯在消息之间居中显示：首条、跨天或相隔至少 5 分钟才展示，今天显示时分，昨天或更早日期带日期说明；普通投递成功状态不再逐条占位。鼠标悬停或手机端点击「引用回复」可引用某条邮件，桌面端也支持右键消息选择引用；输入栏可取消。引用摘要作为独立卡片保存于邮件 HTML 中，并保留 RFC 回复关系，摘要不混入本次正文。

长正文默认折叠；聊天气泡只展示本次回复，不显示标题、历史引用和邮件头操作。中文日期“写道”、英文 wrote、Gmail/Outlook 引用块及常见签名会从展示内容中分离；规则属于启发式识别，不修改原邮件，完整内容仍可在收件箱查看。

邮件中的内嵌图片和 PNG/JPEG/GIF/WebP 图片附件直接展示，点击可放大。站内图片通过已有登录校验的附件接口加载，不公开附件地址；HTML 邮件不直接执行，仅提取文字和图片地址。外部 HTTP(S) 图片按邮件原地址加载，禁止 referrer，忽略明确标记为 1 像素的图片；外部图片服务器仍会收到请求。非图片附件保留下载入口。旧附件 MIME 缺失或被标为普通文件时，也按常见图片扩展名识别，并在浏览器校验真实文件格式后显示；支持仅发送图片。

草稿与附件在本页面内存中保留，发送失败不会清空；刷新页面或离开该功能会丢失未发送草稿。发送重试复用原请求及幂等标识，即使实时更新改变了默认回复目标，也不会自动变成另一封新邮件。

当服务商投递或本地保存过程中发生异常，系统可能无法确认是否已经投递。此时保留草稿和发送尝试，并阻止盲目再次投递；需要先检查「已发送」及服务商记录。此保护优先避免重复邮件，不承诺跨服务商的分布式事务或自动恢复不确定投递。已经确认完成的请求可以安全重试并取得原记录。

## 升级与运行

1. 保留并备份现有 D1 数据。安装依赖，执行 `pnpm --dir mail-vue run build`。
2. 复用上一版本的 `CHAT_NOTIFICATIONS` Durable Object 配置，无需新增聊天服务或凭证。
3. Worker 在处理 HTTP、收信或定时任务前，通过已有 D1 绑定确认并执行兼容升级；升级完成后才进入邮件逻辑。并发首次请求会核实已新增字段，只有确认字段存在才忽略重复添加错误。升级标记按版本记录，成功后缓存当前数据库绑定的就绪状态。无需为部署凭证额外增加独立 D1 API 权限。全新数据库由原有完整初始化流程创建基础表。可选的 `scripts/migrate-mail-chat.mjs` 供拥有 D1 API 权限的管理员手动预升级使用，常规流水线不依赖它。
4. Worker 发布后，执行项目原有 `/api/init/<jwt_secret>` 完整数据库更新流程。GitHub Actions 会自动执行；不要公开实际密钥 URL。迁移可重复执行，不清空现有邮件。随后流水线以只读请求核对线上前端入口与本次构建一致、网站配置可读，以及聊天接口拒绝未登录请求。
5. `src/init/mail-chat-schema.js` 添加会话字段、Reply-To、收信去重/发件幂等字段，以及发送尝试和置顶表。旧版本尚未收集的 Reply-To 不会凭空恢复。
6. 完成后进入 `/mail-chat`。发信权限、域名权限、发送额度和服务商配置沿用已有设置；默认角色禁止发信时，新界面同样不能发送。

生产验证需要使用获准的测试邮箱，检查站外投递、邮件客户端线程关联、投递回调及 Cloudflare Email Routing 的真实来信。仅本地通过不代表站外邮件服务已验证。

## 本地测试

Node.js 24、pnpm 11，启动并初始化使用本地 D1/KV/Durable Objects 的 Wrangler，前端使用 Vite。测试只允许环回地址，不会发出站外邮件。

```sh
node --test test/mail-conversations.test.mjs
MAIL_CHAT_TEST_SQLITE=/absolute/path/to/local-d1.sqlite \
  node --test --test-concurrency=1 test/mail-chat.integration.mjs
```

以上命令在 `mail-worker` 目录执行。`MAIL_CHAT_TEST_SQLITE` 指向当前本地 Wrangler 的 D1 SQLite 文件；默认在本地持久化目录的 `v3/d1/miniflare-D1DatabaseObject/` 下，选择包含 `user` 表的数据库，不要使用 `metadata.sqlite`。集成测试创建独立的本地测试角色与随机邮箱，不修改默认角色；测试数据保留在本地数据库。

集成测试写入本地测试夹具时不要同时运行其他浏览器或测试套件，以免本地 SQLite 写锁干扰。`MAIL_CHAT_TEST_URL` 可指定本地 Worker 地址，默认为 `http://127.0.0.1:8787/`。
