# Mobile viewport behavior (1.21.0)

The mobile web UI uses device width and a fixed 1× page scale, as requested by the site owner. Viewport limits, coarse-pointer `touch-action`, and Safari gesture handlers work together to suppress browser pinch/double-tap zoom. Multi-touch prevention applies only when two or more touches are present; normal single-finger scrolling, tapping, long presses and text entry remain available. Desktop keyboard/browser zoom and operating-system accessibility magnification are controlled by the browser/OS.

Mobile input controls use at least 16px text to prevent Safari's automatic focus zoom. Text autosizing is fixed at 100% during rotation. Dialogs, drawers and long notifications stay within device width. Existing compact chat layout and safe-area padding are retained. One frame-batched VisualViewport source publishes height/offset variables on the document root. Compact layouts, teleported fullscreen dialogs, side drawers and the login form share this visible area during keyboard contraction. Login forms can scroll when the keyboard leaves too little room. The bottom safe area is retained with the keyboard closed and reduced only when a focused field plus viewport contraction identifies an open touch keyboard.

Phone chat headers keep Back, profile/name, Search and a More menu; translation, pinning, group membership and mute controls remain accessible. Frequent header and composer actions use 44px touch targets. Screens narrower than 360px put the text input above the attachment, sticker, voice and send row. On compact touch devices Enter inserts a line break; tap Send or use Ctrl/Command+Enter to send. Desktop Enter-to-send and IME composition remain unchanged. Resizing follows the latest message only when the user was already at the bottom, and never forces a reader away from history.

Sandboxed rich-email documents install the same gesture handlers without changing their sandbox, CSP, link or attachment permissions. Image-viewer controls can still enlarge an individual image; the page remains at 1×.

Validation uses Chromium touch emulation at 320/390/412px portrait widths, 844px landscape width and a simulated keyboard viewport. Checks cover native pinch/double-tap, Safari gesture cancellation, single-finger scrolling, long-press menus, input size, draft retention and settings width. These are simulated mobile checks, not a physical iPhone Safari test; browsers can override page zoom restrictions for accessibility.
